# AIOS Track 1 — гибридная MAS для управления заводнением

Мультиагентная система управления разработкой: языковая модель предлагает
**структурные** гипотезы («перераспределить закачку между этими группами
скважин»), а все **численные уставки** остаются за детерминированным кодом.
Каждый кандидат считается полным прогоном гидродинамического симулятора,
проходит проверку ограничений и оценивается официальным калькулятором ЧДД.

## Задача

Track 1: мультиагентная система оптимального управления на основе
гидродинамической модели. Нужно управлять режимами скважин на горизонте
2014-01-01 .. 2015-12-01 так, чтобы поднять ЧДД, не нарушая эксплуатационных
ограничений, и чтобы каждое число было воспроизводимо.

Вопрос, на который отвечает этот репозиторий: **даёт ли языковая модель
экономический выигрыш, если не позволять ей назначать уставки?**

## Как работает MAS

```
StateCard (состояние на эпоху решения)
  ↓
диагностика / evidence (давление, охват, связность, региональный дисбаланс)
  ↓
LLM: структурные гипотезы            ← GPT-5.6 Sol, только структура
  ↓
Arbiter: структурный отбор кандидатов
  ↓
MagnitudeResolver: численные уставки  ← единственная точка, где рождается число
  ↓
OPM Flow: полный прогон каждого кандидата
  ↓
Guardian: проверка эксплуатационных ограничений
  ↓
ЧДД / экономический отбор
  ↓
закоммиченные управления → следующее реализованное состояние
```

Контур receding-horizon: три эпохи решения, на каждой — свежая диагностика от
фактически реализованного состояния.

## Граница полномочий

> **LLM SETS THE CEILING.**
> **DETERMINISM SETS THE FLOOR.**
> **NO SETPOINTS CROSS.**

Модель расширяет пространство гипотез вверх; детерминированный код держит пол
и остаётся единственным источником численных уставок. Граница проверяется в
коде, а не декларируется: попытка провести численное управление до
MagnitudeResolver отвергается общим сторожем
(`aios.mas.specialists.authority`).

| компонент | что производит |
|---|---|
| LLM (GPT-5.6 Sol) | **структурные гипотезы**: действие, направление, качественная интенсивность, адресация скважин/регионов |
| MagnitudeResolver | **численные уставки скважин** — единственная разрешённая точка |
| OPM Flow | физические результаты симуляции |
| Constraint Guardian | проверка эксплуатационных ограничений |
| Калькулятор ЧДД | экономическая оценка |

Каждое численное управление, доходящее до симулятора, произведено
детерминированным MagnitudeResolver; физические результаты приходят от OPM, а
экономика — от калькулятора ЧДД. Подробная матрица полномочий:
[`docs/team/authority-matrix.md`](docs/team/authority-matrix.md).

## Замороженный результат

`KT3-FINAL-EVIDENCE-PATCH-001` — один замороженный прогон бенчмарка на три
эпохи решения, кейс Model Y, код `3582a40`.

| вариант | ЧДД, сопоставимый с организаторским, млн ₽ |
|---|---|
| опорное расписание (`B0_BASELINE`) | 5326.453496 |
| MAS OFF (детерминированная абляция) | 5325.046561 |
| MAS ON (гибридная MAS, GPT-5.6 Sol) | **5412.255034** |
| **прирост MAS ON над MAS OFF** | **+87.208** |

Точные значения ЧДД на горизонте управления 2014-01-01 .. 2015-12-01:
1082.233754138962 / 1079.492035705738 / 1249.4366799710856 млн ₽. Класс
сравнения `NORMALIZED_COMPARABLE`, `win_claimable: true`: варианты проходят
одну и ту же физику, один и тот же Guardian и одну и ту же экономику.

Guardian траектории активен: у закоммиченного кандидата **5904 проверки, 0
нарушений** (33 538 проверок по всему поиску). Итоговое расписание —
`wells_schedule.inc`, sha256
`6e95f8dc825d3f16ebbdb12ecfe5c73e85e205445f6930de0852fce2b8ee7dbe`, 24 шага
`DATES` c 2014-01 по 2015-12.

Что этот результат **не** утверждает. Это **один** прогон: не глобальный
оптимум, не статистическая значимость, не устойчивость по повторным прогонам,
не тождество с tNavigator и не подтверждённый организатором допуск.

Раскрываем прямо: из трёх эпох решения **две** прошли живой моделью, а третья
(2015-04-01) после ошибки провайдера закрылась детерминированным полом
(`provider_error` → `HOLD`). Прирост получен двумя живыми эпохами, а не тремя.

Предыдущее замороженное измерение `PERF-004-CAUSAL-CLEAN-001` (код `205ad86`,
MAS ON 5342.722480331016 млн ₽, +17.68) остаётся в
[`submission_evidence/`](submission_evidence/) как исторический архив и
**заменено** результатом выше.

## Физический механизм

Закоммиченные траектории MAS OFF и MAS ON совпадают на T0 и T1 и расходятся
только после последней эпохи решения. Там закоммиченное расписание
перераспределяет закачку между скважинами при **точно сохранённой суммарной
заданной закачке** (3060.00 → 3060.00 м³/сут, ошибка сохранения
0.0000000000): пять доноров отдают 866.25, четыре получателя принимают
866.25.

За окно управления MAS ON дал примерно **+8 946 м³ нефти** при **−54 540 м³**
суммарной закачки воды: больше нефти при меньшей закачке. Ограничения не
ослаблялись — нижний порог забойного давления добывающих (50 бар) и верхний
предел нагнетательных (300 бар) одинаковы в обоих вариантах.

## Быстрый запуск

```bash
mise trust     # разрешить локальную конфигурацию (mise.toml) в свежем клоне
mise install
mise run bootstrap
mise run check
```

`mise trust` нужен один раз на свежем клоне: без него mise отказывается
читать `mise.toml` из-за правил доверия, и `mise install` падает сразу.
CI (`mise-action`) доверяет конфигурацию за вас, поэтому в пайплайне этот
шаг не нужен — он про ручной запуск на машине разработчика или организатора.

Демонстрация проверенного снимка экспериментов — без Docker и без внешних
материалов:

```bash
mise run kt1-demo
```

## Внешние данные

Колода Model Y и официальный пакет расчёта ЧДД **намеренно не входят в
репозиторий**: это материалы организаторов, и их место — вне системы
контроля версий. Репозиторий содержит код, конфигурацию и агрегированные
свидетельства экспериментов.

Настройка не требует правки исходного кода:

```bash
cp .env.example .env
# и указать свои пути:
#   MODEL_Y_ROOT=/path/to/model-y      # каталог с MODEL_Y.DATA
#   CHDD_ROOT=/path/to/chdd-python     # каталог с chdd_model.py
```

Без этих переменных работают проверки и демонстрация; живые прогоны
останавливаются с явным сообщением о том, какая переменная не задана.

Живые команды (нужны Docker и внешние материалы):

```bash
mise run validation-demo   # сквозной прогон и пакет сабмишена
mise run exp001            # экран перераспределения закачки
mise run exp003            # конверт робастности
```

## Hybrid MAS v1.1

Специалисты (Production, Injection), Arbiter, MagnitudeResolver, Orchestrator и
PredictiveSafetyScreen **реализованы и работают в замкнутом контуре MAS**.
Замороженное измерение `KT3-FINAL-EVIDENCE-PATCH-001` выполнено именно этим
контуром. Типизированные контракты и инварианты, на которых он стоит:
`docs/architecture/mas-v1.1-contracts.md`,
`docs/architecture/mas-v1.1-diagnostics.md`,
`docs/architecture/mas-v1.1-magnitude-resolver.md`.

Доказано ровно то, что измерено: один замкнутый прогон бенчмарка на три эпохи
решения. Это не заявление о промышленной зрелости.

Точка входа для новых участников команды: [docs/team/README.md](docs/team/README.md).

## Историческая линия EXP001-004 (superseded)

Завершённая экспериментальная линия по перераспределению закачки с
**фиксированным** расписанием — до появления замкнутого MAS-контура. Не
переписывается задним числом и **не является текущим результатом**:

| | млн ₽ (историческая шкала, START-stamp) |
|---|---|
| Базовый сценарий | 1030.877696 |
| Лучший из просчитанных сценариев EXP003 | 1190.593386 |
| Прирост | +159.715690 (+15.493 %) |

`REFERENCE_ONLY / PRE-END-STAMP`. Эти числа получены до исправления
attribution интервалов ЧДД (`c320087`) и описывают расписание, которое
текущий код уже не строит. Сопоставлять их с замороженным результатом MAS
напрямую **нельзя**: другая шкала, другой механизм, другая рамка сравнения.
Текущий заявляемый результат — в разделе «Замороженный результат» выше.
Разбор: [`docs/benchmark/mas-v1.1-benchmark.md`](docs/benchmark/mas-v1.1-benchmark.md).

## Воспроизводимость

Демонстрация читает сохранённые материалы экспериментов и не пересчитывает
их. Живые расчёты воспроизводятся отдельными командами и начинаются со
сверки базового сценария.

## Что уже доказано

- контрольный расчёт воспроизводит базовый сценарий точно, вместе с SHA
  файла расписания, и каждый эксперимент начинается с этой сверки;
- построенный экономический вход байт в байт совпадает с эталонным;
- бинарные результаты симулятора совпадают с опорным расчётом.

## Что ещё требует подтверждения

- **эквивалентность tNavigator.** Массовый мост между объёмами OPM и
  массами калькулятора не сверен с эталонной выгрузкой tNavigator.
  Плотности взяты из колоды, но равенство величин не подтверждено —
  отсюда пометка `NOT_OFFICIAL_PENDING_TNAV_REFERENCE`.
- **трактовка водного баланса.** Водный учёт поверхностный, по модели. Это
  не VRR и не замещение отбора в пластовых условиях; официальное правило не
  определено — отсюда `ORGANIZER_RULE_UNRESOLVED`.
- **порог по давлению в исторической линии EXP001-004.** На момент того прогона
  официальный порог не был подключён к проверке ограничений, поэтому там
  пластовое давление осталось метрикой риска, а не ограничением. С тех пор
  организаторские значения подтверждены (см. `docs/team/organizer-constraints.md`)
  и используются в MAS-контуре (`aios.state`, `aios.agents.constraint_guardian`).

Эти пометки — часть результата, а не оговорки: по ним видно, что именно
проверено, а что ещё нет.
