# Контур сабмишена Track 1

Минимальный сквозной путь от кейса до пакета сабмишена:

```
CASE → загрузка кейса → история + ограничения → восстановление состояния
     → политика → генератор расписания → wells_schedule.inc
     → OPM Flow → траектория → 14-колоночный вход ЧДД
     → официальный CHDD_PYTHON → пакет сабмишена
```

Оптимизатора здесь нет. Задача этой версии -- доказать, что контур целиком
работает и воспроизводит уже полученный baseline, а не улучшить результат.

## Вход

Единственный вход -- файл кейса (`cases/model_y_validation.json`). В нём
лежит всё, что зависит от конкретной задачи:

| Секция | Что задаёт |
|---|---|
| `management_start_date`, `management_end_date` | окно управления |
| `history` | физическая колода и её файл расписания |
| `constraints` | допустимые управления и технологические пределы |
| `economics` | путь к официальному калькулятору ЧДД, нормативы, плотности |
| `simulator` | закреплённый docker-образ OPM Flow |
| `acceptance` | опорное значение NPV для сверки (необязательно) |

Относительные пути разрешаются от каталога самого файла кейса.

В коде захардкожены только два инварианта Track 1, оба доказаны лабораторно:
`WLPR > 500` роняет весь расчёт ЧДД, и перевод добывающей скважины в
нагнетательные на треке запрещён. Кейс, который пытается их ослабить,
отклоняется при загрузке.

## Запуск

```bash
mise run bootstrap
mise run validation-demo
```

Нужен запущенный Docker: симулятор берётся из закреплённого по digest образа
`openporousmedia/opmreleases`. Локально установленный `flow` намеренно не
ищется -- посчитать другим симулятором и назвать это тем же baseline нельзя.

Полный прогон занимает примерно полторы минуты, из них около 80 секунд --
сама симуляция.

Аргументы (`--case`, `--output`, `--runtime`, `--policy`) позволяют указать
другой кейс или политику; значения по умолчанию соответствуют команде выше.

## Что делает контур

1. **Кейс.** Разбор и проверка контракта. Молчаливая подстановка умолчаний
   запрещена: незаполненная секция -- это ошибка, а не «как-нибудь».
2. **История.** Файл расписания колоды разбирается парсером свободного
   формата ECLIPSE. Граница окна находится по реальному блоку `DATES`.
3. **Состояние.** История проигрывается блок за блоком, и на начало окна
   получается срез: роль, статус, режим и уставки каждой скважины. Для
   Model Y это 49 известных скважин, 33 добывающих и 16 нагнетательных.
4. **Политика.** `BASELINE_CONTINUATION` (по умолчанию) повторяет опорные
   воздействия окна. `NO_CHANGE` замораживает восстановленный срез на всё
   окно, сохраняя сетку дат кейса.
5. **Генератор.** Собирает `wells_schedule.inc`. Порядок шагов и скважин
   детерминирован, чисел -- одна функция форматирования, времени генерации в
   файле нет. Одинаковый вход всегда даёт одинаковый SHA-256.
6. **Ворота.** До симуляции: существование скважины, дата в окне,
   хронология, неприкосновенность истории, допустимость режима управления,
   отсутствие смены роли, предел `WLPR`, конечность уставок, пределы BHP,
   лимит закачки по объекту, отсутствие противоречащих управлений.
   Любая непройденная проверка останавливает пайплайн.
7. **OPM.** Собирается временная рабочая копия кейса: файлы физической
   модели **копируются**, история переносится байт в байт, окно --
   сгенерированным файлом. Копия, а не жёсткая ссылка: ссылка делит inode
   с исходной колодой, и любая запись в рабочую копию испортила бы оригинал.
   Исходная колода не меняется никогда.
8. **Траектория и ЧДД.** Из сводки строится 14-колоночный вход, приросты --
   внутри одной скважины, подаётся вся история (состояние ЭЦН зависит от неё).
   Считает официальный пакет `CHDD_PYTHON`, формулы не дублируются.
   Результат разбирается строго: пропущенное или нечисловое обязательное поле
   даёт отказ, а не подставленный ноль.

## Выход

```
output/                   -- публикуется только при полном проходе
  wells_schedule.inc      -- сабмишен
  claimed_npv.json        -- заявленный результат и его происхождение
  validation_report.json  -- все ворота, диагностика, вердикт
  run_manifest.json       -- кейс, хеши входов, команда запуска, версии
runtime/
  chdd_input.csv          -- 14-колоночный вход калькулятора
  staging/                -- расписание текущего прогона до публикации
  workspace/              -- рабочая копия колоды и лог симулятора
```

Каталоги `output/` и `runtime/` не версионируются: они содержат абсолютные
пути окружения и результат конкретного прогона.

## Закрытый отказ

Пакет сабмишена публикуется транзакционно.

1. Прогон начинается со снятия пакета прошлого прогона. С этого момента на
   диске нет результата, который можно принять за итог начатого расчёта.
2. Вся изменяемая работа идёт в `runtime/staging`. Расписание, не прошедшее
   ворота, остаётся там для разбора и сабмишеном не становится.
3. При успехе публикуются все четыре файла, `claimed_npv.json` -- последним:
   его наличие означает, что остальное уже лежит рядом.
4. При провале в `output/` появляются только `validation_report.json` и
   `run_manifest.json`, оба со `status: FAILED` и `verdict: BLOCKED`. Ни
   заявленного NPV, ни файла расписания не публикуется.
5. Любое исключение на любой стадии -- включая нечитаемую сводку OPM и сбой
   официального калькулятора -- приводит к провалу прогона, а не к выходу
   мимо публикации. `KeyboardInterrupt` и `SystemExit` не перехватываются,
   но пакет прошлого прогона к этому моменту уже снят.

## Сверка с baseline

На Model Y контур воспроизводит уже полученный лабораторный результат:

| Величина | Значение |
|---|---|
| NPV | 1030.877696 млн руб |
| Экономических месяцев | 23 (2014: 12, 2015: 11) |
| Нефть / жидкость / закачка | 213.695 тыс. т / 1976.609 тыс. т / 1962.961 тыс. м³ |
| Активных скважино-месяцев | 1127 |
| События ЭЦН / стоп / пуск / перевод | 1 / 0 / 0 / 0 |
| Версия калькулятора | `7.0.2-negative-row-filter` |

Совпадение точное, а не в пределах допуска: построенный контуром вход
калькулятора байт в байт равен эталонному, а `EGRID`, `INIT` и `UNRST`
симулятора побитово совпадают с опорным прогоном. Из векторов сводки
расходится единственный -- `TCPU`, то есть затраченное процессорное время.

Допуск сверки задан кейсом (`acceptance`) и равен 1e-6 млн руб. Разница,
которую печатает демо, -- это разница с опорным числом, округлённым в кейсе
до шести знаков.

## Почему NPV всё ещё не официальный

Происхождение результата -- `NOT_OFFICIAL_PENDING_TNAV_REFERENCE`, и это
не формальность. OPM отдаёт объёмы, а калькулятор ждёт массы, поэтому между
ними стоит массовый мост:

```
WOMT = WOPT × 0.832 т/м³
WWMT = WWPT × 1.0128 т/м³
WLPT = WOMT + WWMT
```

Плотности взяты из `DENSITY` самой колоды -- это точный факт. Не доказано
другое: что построенные так `WOMT` и `WLPT` численно совпадают с `womt` и
`wlpt`, которые выгружает tNavigator. В частности, неизвестно, считает ли
tNavigator массу жидкости той же суммой или использует другую плотность воды
либо сепараторную модель.

До сверки с эталонной выгрузкой tNavigator число остаётся кандидатским.
Называть его официальным нельзя, и пометка снимается только вместе с этой
сверкой.

Открыты также вопросы, не влияющие на воспроизводимость контура, но влияющие
на трактовку результата: считается ли 11-месячный 2015 год полным при
дисконтировании и бесплатен ли начальный парк ЭЦН на 01.01.2014.
